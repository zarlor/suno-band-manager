# Memory System for Mac — the v2 Sanctum

**Sanctum location:** `{project-root}/_bmad/_memory/band-manager-sidecar/`

> **Preserved divergence (documented):** Mac's sanctum lives under the
> **double-underscore** `_memory` parent, NOT the v2-default single-underscore
> `memory/{skill}/` parent. The path is load-bearing — portable sync and the
> reconcile tooling depend on it. Do not "fix" it to the v2 default.

Where other things live: the load set is the wake's `sanctum_load_order` plus the sanctum's INDEX.md; the write rule is in `access-boundaries.md`; the consolidating save is `references/save-memory.md`; First Breath is `references/init.md`; the post-sync reconcile is step 2 of `references/activation.md`; Pulse is the sanctum's `PULSE.md`.

## Tokens are the budget

Everything that loads on waking is paid every session, so it is budgeted in tokens, not lines — a line count passes a file whose few lines each hide a session narrative. `scripts/check-memory-health.py` measures it (characters / 4 as the estimate):

- **MEMORY.md** — aim near ~1,500 tokens; flagged past ~3,000, or when any line runs past ~600 characters (a packed line).
- **The whole spine** (the seven always-loaded files) — flagged past ~12,000 tokens.
- **The two companion files** (voice file, mac-preferences) — each flagged past ~20,000 tokens. Over budget means *offer the owner a compaction pass*; they are never digested or split on Mac's own initiative.
- **patterns.md / chronology.md** — not loaded on waking; generous character ceilings catch only runaway growth.
- **sessions/** — raw, never flagged.
- It also lists organic sanctum files INDEX.md doesn't mention — an unlisted file is a lost file.

## The two tiers — sessions → MEMORY

- **`sessions/YYYY-MM-DD.md` (raw, not loaded on waking)** — each session's play-by-play: workshop detail, the story behind a publish. The durable record; nothing is lost here.
- **`MEMORY.md` (curated, loaded every waking)** — what the owner is doing and prefers right now: preferences, the downloads budget, exclusions, active band profiles, current and pending work, the Pulse report, module state, and the derived catalog sections (between `<!-- derived:… -->` markers, regenerated by `scripts/regenerate-index-sections.py`, never hand-edited).

Append raw to `sessions/`; distill up into MEMORY.md. When a Current Work block ages into history, its detail moves down to `sessions/` and MEMORY.md keeps a one-line pointer.

## Capture as you go

Write the moment something is worth keeping — the owner may end the session without a word. Under the write rule in `access-boundaries.md`, most of these need no permission:

- **Tier change** ("I upgraded to Pro") → MEMORY.md User Preferences, update the Downloads cap, say what's newly available, offer to revisit band profiles.
- **Default mode change** → MEMORY.md.
- **Exclusion** ("I never want autotune") → MEMORY.md Default Exclusions; note if it affects a band profile.
- **A durable behavioral correction** (how Mac talks, paces, frames) → append to `docs/mac-preferences.md` the same turn it lands.
- **Downloads** → see below.
- After a create-song or refine-song cycle, a **state checkpoint** in MEMORY.md Current Work: song title, style prompt (first ~100 characters), model, band profile, mode, refinement round. If context compaction drops the conversation, this is how Mac picks the thread back up; the full detail stays in `sessions/`.

### Downloads

Suno caps song downloads per tier (numbers in `references/SUNO-REFERENCE.md`). MEMORY.md `## Downloads` holds the owner's cap, the count used this cycle, and the reset date.

- When the owner says they downloaded, update the count that turn. When the reset date passes, start the count over.
- When a keeper is picked, mention what's left in a few words ("that leaves you 6 this cycle").
- Keep the steer: listen in the browser, download only the keeper — or a take that needs measuring — not every take.

## Which file

Before writing, ask: is it worth remembering, what's the least that captures it, and where does it go?

- Raw session detail → `sessions/YYYY-MM-DD.md`
- Live state, preferences, current/pending work → `MEMORY.md`
- Musical quirks and recurring feedback patterns about the owner → `patterns.md` (show it before writing — it's Mac's conclusion about them)
- Significant timeline events → `chronology.md`, when the sanctum has one
- A shift in how Mac shows up, or what lands with the owner → one line in PERSONA.md's Evolution Log or BOND.md's notes
- A new organic file → also a row in `INDEX.md`

## The companion files (in `docs/`, not the sanctum)

They live in `docs/` so they travel in portable sync; the sanctum is per-machine and does not. Both load whole on every waking.

### `docs/voice-context-{username}.md` — who the owner is

The durable creative identity, the "slow memory" (MEMORY.md is the fast one). One file per user, named by the normalized username (lowercase, spaces to hyphens); Mac writes only to the current user's file.

Sections: **Who I Am** (history, background, what drives them) · **How I Write** (form, themes, emotional drivers, evolution, influences) · **How to Work With Me** · **Creative Catalog** (songs, albums, playlist structure) · **Suno Preferences** (tier, models, voice, sliders, exclusions — production learnings belong in skill references and `patterns.md`, not here) · **Session History** (condensed milestones) · **Current Creative State** (active WIPs, threads to pick up).

**Companion Files table** near the top indexes satellite documents loaded on demand:

| File | What | When to load |
|------|------|-------------|
| `docs/example-deep-dive.md` | Detailed context on [topic] | When discussing [trigger] |

Add the row in the same batch that creates the satellite file.

**Creating:** when no voice file exists and meaningful personal context has emerged, offer to start one. **Updating:** only for genuinely new durable context, under the write rule — routine sync edits just happen; substantive identity additions are written in the owner's words and shown in the same turn. **Size:** when it runs past budget, offer to compact — summarize older history, merge duplicates, keep the personal sections whole.

### `docs/mac-preferences.md` — how the owner wants Mac to talk

Durable behavioral preferences: communication style, pacing, framing, meta-conversation rules. A different question from the voice file — not "who is this person creatively?" but "how do they want me to talk with them?"

It lives in `docs/` because harness-local memory (e.g. a CLI's per-machine memory directory) doesn't travel in the sync archive. Machine-local facts (env vars, auth, per-machine workflow notes) can stay in harness memory; behavioral preferences can't.

Each entry: a title and one-line description, why it matters (the correction behind it), how to apply it, cross-references where useful. Append in the same turn the correction lands — the session may end at any point.

Doesn't belong here: Suno platform knowledge (→ the module's skill references), musical preferences (→ `patterns.md` or the voice file), band or catalog policy (→ band profiles or the voice file), session state (→ MEMORY.md).
